# OpenStack Prometheus Autoscaling Layer

[Türkçe](README.md) | [English](README.en.md)

---

An integration layer providing CPU-based autoscaling for OpenStack environments using a modern **Prometheus + Alertmanager + libvirt-exporter** architecture instead of the legacy Ceilometer, Gnocchi, and Aodh telemetry stack.

---

## Architecture and Workflow

```text
┌─────────────────┐       ┌────────────────────────┐
│ libvirt-exporter│ :9177 │ server-group-exporter  │ :9102 (60s TTL Cache)
│  (Raw CPU Data) │       │ (Nova Metadata/StackID)│
└────────┬────────┘       └───────────┬────────────┘
         │                            │
         └──────────────┬─────────────┘
                        ▼
             ┌──────────────────────┐
             │      Prometheus      │ :9090 (PromQL Vector Matching)
             │   (Avg CPU > 70%?)   │
             └───────────┬──────────┘
                        ▼
             ┌──────────────────────┐
             │     Alertmanager     │ :9093 (Webhook Router)
             └───────────┬──────────┘
                        ▼
             ┌──────────────────────┐
             │ heat_signal_adapter  │ :9200 (Keystone Token Bridge)
             └───────────┬──────────┘
                        ▼
             ┌──────────────────────┐
             │     Heat Engine      │ :8004 (Scale-Out / Scale-In)
             └──────────────────────┘
```

1. **libvirt-exporter (:9177):** Collects raw CPU time metrics directly from KVM/libvirt for each instance domain.
2. **server-group-exporter (:9102):** Queries Nova API to map instance domains (`instance-XXXXXXXX`) to their Heat Stack ID (`metering.server_group`). Employs a 60-second TTL cache to minimize API and database load.
3. **Prometheus (:9090):** Performs PromQL vector matching on the `domain` label to dynamically join CPU metrics with Stack IDs and calculates the average CPU utilization.
4. **Alertmanager (:9093):** Evaluates thresholds and routes active alerts to the local webhook adapter.
5. **heat_signal_adapter (:9200):** Receives the webhook alert, fetches a valid Keystone token, and executes an authenticated `POST` request to the Heat scaling policy signal URL.

## Prerequisites

Ensure the following components are available on the target host:
* A functional OpenStack deployment (Nova, Heat, Keystone, KVM/libvirt)
* Python 3 and `python3-venv` package
* Prometheus and Alertmanager instances
* `prometheus-libvirt-exporter` (Default port: 9177)
* OpenStack RC credentials file (`/root/openrc`)

## Installation and Configuration

### 1. Configure Heat Signal URLs
Retrieve the scaling policy signal URLs generated by your Heat template:
```bash
openstack stack output show <STACK_NAME> scaleup_url
openstack stack output show <STACK_NAME> scaledown_url
```

Define these URLs in `adapter/heat_signal_adapter.py` or set them as environment variables:
```bash
export HEAT_SCALEUP_URL="https://<OPENSTACK_IP>:8004/v1/<PROJECT_ID>/stacks/<STACK>/<ID>/resources/scaleup_policy/signal"
export HEAT_SCALEDOWN_URL="https://<OPENSTACK_IP>:8004/v1/<PROJECT_ID>/stacks/<STACK>/<ID>/resources/scaledown_policy/signal"
```

### 2. Automated Installation
Clone or copy the repository to the target server and run the setup script:
```bash
cd openstack-prometheus-autoscaling
sudo bash setup.sh
```

The script copies files to `/opt/openstack-bridge`, configures the Python virtual environment, installs requirements, and enables the systemd services.

### 3. Manual Installation (Alternative Step-by-Step)
If you prefer not to use the automated script or need to troubleshoot:

#### A) Create Directories and Copy Files:
```bash
sudo mkdir -p /opt/openstack-bridge/exporters /opt/openstack-bridge/adapter /etc/prometheus /etc/alertmanager

sudo cp -r exporters/* /opt/openstack-bridge/exporters/
sudo cp -r adapter/* /opt/openstack-bridge/adapter/
sudo cp configs/prometheus.yml /etc/prometheus/prometheus.yml
sudo cp configs/alert_rules.yml /etc/prometheus/alert_rules.yml
sudo cp configs/alertmanager.yml /etc/alertmanager/alertmanager.yml
```

#### B) Initialize Python Virtual Environment:
```bash
sudo python3 -m venv /opt/openstack-bridge/venv
sudo /opt/openstack-bridge/venv/bin/pip install --upgrade pip
sudo /opt/openstack-bridge/venv/bin/pip install -r requirements.txt
```

#### C) Install and Enable Systemd Services:
```bash
sudo cp systemd/*.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now server-group-exporter
sudo systemctl enable --now heat-signal-adapter

# Reload Prometheus and Alertmanager
sudo systemctl restart prometheus alertmanager
```

> **Debugging / Direct Terminal Execution:** To run and test without systemd services:
> ```bash
> source /root/openrc
> /opt/openstack-bridge/venv/bin/python3 /opt/openstack-bridge/exporters/server_group_exporter.py
> # In a separate terminal:
> /opt/openstack-bridge/venv/bin/python3 /opt/openstack-bridge/adapter/heat_signal_adapter.py
> ```

## Verification and Testing

### Service and Metric Checks
```bash
# Check service status
systemctl status server-group-exporter
systemctl status heat-signal-adapter

# Test exporter output (should list instance domain to Stack ID mappings)
curl -s http://localhost:9102/metrics
```

### Prometheus PromQL Vector Matching Test
Execute the PromQL query via Prometheus Web UI (`:9090`) or API:
```promql
avg by (server_group) (
  rate(libvirt_domain_info_cpu_time_seconds_total[5m]) 
  * on(domain) group_left(server_group) 
  openstack_instance_server_group
)
```
> **Expected Output:** Normalized average CPU utilization per stack group (between `0.00` and `1.00`).

### End-to-End Autoscaling (Stress) Test
1. SSH into an instance belonging to the Heat AutoScalingGroup and generate CPU load:
   ```bash
   cat /dev/zero > /dev/null &
   ```
2. **Scale-Out Verification:** Once average CPU exceeds 70% (`> 0.70`), Prometheus triggers `CpuHigh`, Alertmanager routes to the adapter, and Heat launches a new VM.
3. Terminate the CPU stress process:
   ```bash
   killall cat
   ```
4. **Scale-In Verification:** When CPU utilization drops below 20% (`< 0.20`), `CpuLow` triggers and Heat terminates the surplus VM.

## Key Design Principles

1. **Agentless Architecture:** Requires no guest agent inside instances; all metrics are collected directly at the hypervisor level via libvirt.
2. **PromQL Vector Matching:** Preserves standard `libvirt-exporter` behavior by performing metadata enrichment at query time using `* on(domain) group_left(server_group)`.
3. **TTL Caching:** Caches Nova instance metadata for 60 seconds, reducing OpenStack API and database queries by ~75%.
4. **Keystone Token Bridge:** Transforms unauthenticated Alertmanager webhook alerts into authenticated OpenStack Heat API calls.
